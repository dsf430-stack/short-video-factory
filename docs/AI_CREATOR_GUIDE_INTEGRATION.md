## 邊界
- 此層只負責定位、選題、查證、腳本審查、發布、數據復盤與商業化決策。
- 不改變 handdraw、motion_hub、068 聲音、字幕、圖像、Actions、active-job.json、catalog 或任何渲染入口。
- 59條是營運檢查項目，**不是**已安裝的59個程式功能，也不是自動出片引擎。
- 不虛構觀看數、營收、產品測試、成功影片或來源。無數據標記 UNKNOWN。
- 不要求額外付費 API；新增外部服務前先確認成本與授權。

## 十類映射（59條）
| 類別 | 操作卡 | 與現有系統的接點 |
|---|---|---|
| 定位 | 01-01～01-06 | 定義觀眾、內容承諾、首月可驗證指標 |
| 選題 | 02-01～02-07 | 熱搜候選、來源連結、100分選題卡與狀態 |
| 核實 | 03-01～03-06 | 官方資料、最小實測、事實可信度、素材匿名化 |

| 圖文 | 06-01～06-05 | 可選擇衍生封面、步驟圖與長文 |

## 後續驗收順序
1. 核對現有選題/任務入口與資料結構，再決定是否接上機器可讀的營運資料；不要直接覆蓋 active-job.json。
2. 單獨測試一個新選題的評分、來源、腳本檢查，確認不會改動影片製作參數。
3. 如需自動串接，先提出單一最小程式變更並以現有測試及 GitHub Actions 驗證。
4. 只有實際生成並驗證 MP4，才回報「出片成功」。
